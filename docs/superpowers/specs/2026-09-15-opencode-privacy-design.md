# OpenCode Privacy 设计

日期：2026-09-15

状态：设计提案；未实现，未声称功能已验证。

## 1. 目标与约束

在不修改、打补丁或 fork OpenCode 核心的前提下，尽量移植 pi-privacy 的隐私保护功能，再增加账户、密码及其他敏感配置的可逆替换与受控使用能力。

采用 OpenCode 插件、自定义工具、本地凭据代理和可选的模型传输适配器。实验性接口必须有版本兼容检测。不能安全覆盖的功能明确显示为不支持，不能静默退化为已保护。

“完整移植”是覆盖目标，不是已实现声明。实现时固定两个上游的提交版本，逐项建立源码、测试和功能对应表，并保留复用代码的许可证及归属。

## 2. 架构

- privacy-core：纯 TypeScript 检测器、脱敏、策略、隐私等级、审计事件模型。
- opencode-adapter：消息、系统提示、工具参数、工具结果、模型选择和压缩等插件接入点。
- credential-broker：本地凭据存储、引用解析、授权校验和受控操作执行。
- operation-adapters：配置文件、HTTP 和后续 CLI/MCP 操作适配器。
- provider-adapters：ZDR 路由与特定供应商的证明验证及请求传输。
- local-cli：独立于聊天的凭据录入、策略管理和状态查询入口。

普通工具和模型使用不含原值的引用。代理不向模型暴露读取原始凭据的接口。引用不是授权令牌，知道引用不能取得任意用途的访问权限。

## 3. pi-privacy 功能映射

| 功能 | 无核心修改的实现方向 | 验收边界 |
| --- | --- | --- |
| PII / secret 检测 | 本地确定性检测器、允许列表、中文规则扩展 | 模式检测无法识别全部语义隐私 |
| 模型发送前检查 | 消息及系统转换钩子；验证后的传输适配器 | 标题、摘要、压缩、重试、子任务需逐条实测 |
| 工具调用外发控制 | 执行前策略、命令结构及敏感文件引用检查 | 不将任意程序的网络行为视为可完全静态识别 |
| 工具结果脱敏 | 执行后清洗文本、标题、可处理元数据 | 中间事件、附件、错误路径需要独立验证 |
| 模型降级保护 | 按会话记录模型等级与发送授权，发送前重新判断 | 不仅检查界面切换事件；子模型同样检查 |
| 本地模型识别 | 检查实际端点，显示可观察证据 | loopback 可能是转发服务，不保证模型本地执行 |
| OpenRouter ZDR | 传输适配器对实际请求施加并验证路由约束 | 仅对经过适配器的请求声明 enforced |
| TEE 验证 | 复用合法可用验证器，绑定实际请求连接和证明 | 无法完成连接绑定时标记 unverified |
| 模型隐私等级 | 状态命令、提示与可用 UI 扩展 | 供应商声明和验证证据分开显示 |
| 工具来源 / surface | SDK、已知配置与调用记录形成来源及暴露面报告 | 未知来源明确为 unknown；不宣称全局网络监控 |
| 会话控制 | warn / redact / block / off 等按功能设置，记忆授权 | PII 关闭不自动关闭凭据保护 |
| 无人值守 | 明确配置下自动脱敏；敏感外发无法授权则拒绝 | 不因为没有交互界面就允许泄漏 |
| 策略信任 | 用户策略为底线，隐式项目配置只能加强 | 项目文件不能增加允许列表或关闭审计 |

交互操作必须由真实用户界面或本地 CLI 发起。模型可以查询状态，但不能通过工具降低保护等级、增加授权目标或批准自己的操作。

## 4. 新增凭据能力

### 4.1 录入和引用

本地 CLI 使用隐藏输入录入，不通过命令行参数接收明文密码，不将凭据放入 OpenCode 的全局环境变量。采用随机不透明 ID，可附加不敏感用途标签；模型看到 secret://<id>。

代理保存原值，插件只获取执行引用和必要的匹配能力。第一阶段允许受信任的插件进程在内存中持有用于精确脱敏的值，但不得把此模式称为与 OpenCode 进程隔离；严格隔离模式由代理提供批量脱敏接口，插件不持有原值。

凭据使用操作系统凭据存储的适配层；首个平台为当前 macOS Keychain。缺少受支持存储时拒绝持久保存，不回退明文 JSON。Linux、Windows 作为独立适配阶段。

### 4.2 执行路径

1. 模型生成只含引用的结构化工具调用。
2. 自定义工具把引用、操作和目标传给代理。
3. 代理根据可信用户策略检查引用、工具、字段、目标、路径和会话授权。
4. 操作适配器内部恢复原值；不修改 OpenCode 公共 tool args 为真实值。
5. 在输出、异常、进度信息离开适配器前清洗敏感值。
6. 返回状态和脱敏结果，审计仅记录引用 ID、规则和结果。

拒绝未知、失效、越权或跨会话未授权引用；绝不能把未解析占位符当真实密码继续提交。凭据在模型切换到本地或 TEE 时仍然保持隐藏。

### 4.3 操作适配

- 配置文件：支持明确格式的字段级读取/更新，读取返回稳定引用；用文件版本校验阻止并发覆盖；写入原子替换并校验目标路径、符号链接和权限。不得向模型暴露带真实值的 diff、备份或错误。若目标程序必须读取明文配置，要明确该目标文件含明文，不能称为全磁盘无明文。
- HTTP：允许指定 HTTPS 目标、方法和敏感字段；默认不跟随重定向，校验解析目标及私网策略，禁止凭据改发到其他主机；不将敏感值用于任意 URL、日志或错误文本。
- CLI：按可执行文件和固定参数结构逐个适配；避免 shell 字符串插值及进程参数携带密码。只有经过审计的命令才能获得恢复后的值。
- MCP：默认只传占位符；只有明确受信任且完成适配的服务才允许使用凭据。远程服务接收明文属于明确授权的数据披露，不声称远程工具看不到秘密。

前两个适配器先实现，CLI/MCP 后续逐个扩展；pi-privacy 功能范围不因这个顺序而缩减。

## 5. 安全边界

纯插件无法保证阻止同用户下任意 shell、恶意插件、恶意 MCP 或本机管理员读取文件、调用代理或外发数据。Unix socket 权限与独立进程只减少暴露面，不构成对同用户任意代码的完整授权隔离。

默认兼容模式提供尽力防护。增强限制模式通过工具权限和受控适配器减少绕过；在完成操作系统沙箱及身份隔离之前，不宣称能抵御同用户恶意代码。代理不能靠可被同用户读取的静态 token 达成这种保证。

图片、附件、任意编码、分片、哈希、截取与未知程序副作用不能靠文本替换完整覆盖。已支持适配器必须尽量在明文产生之前限制行为；不支持的敏感调用拒绝执行并说明原因。

已写入历史会话的秘密不会因安装插件自动消失。历史扫描、备份处理和删除属于单独且需明确范围的维护功能。

## 6. 错误和配置行为

代理不可用、存储锁定、策略无效、引用无法解析或隐私验证失败时，敏感操作失败关闭。错误消息只含固定错误码和脱敏信息，不包含原始异常对象。

已授权操作不重复询问；新目标、新用途、模型供应商变化按对应策略重新校验。PII 允许列表不得解除凭据引用的用途限制。

审计数据保留为最小元数据，不记录请求体、凭据、完整敏感路径。提供明确的审计开关及保留策略，项目不能降低用户配置。

## 7. 测试与交付顺序

### 阶段 A：兼容性与防护基础

固定 OpenCode 和 pi-privacy 上游版本；审计 pi-privacy 各功能的实际实现及许可证。建立 OpenCode 调用路径测试：普通消息、系统提示、标题、摘要、压缩、子任务、工具参数、运行中元数据、输出、异常、附件、用户 shell、重试。

优先实现检测、策略、文本脱敏、工具调用检查、配置底线和状态报告。每项以 supported / partial / unsupported 报告真实覆盖情况。

### 阶段 B：凭据使用

实现 macOS 存储、本地录入、引用、代理、配置文件及 HTTP 操作。用随机测试凭据验证目标端实际收到原值，同时模型捕获请求、插件日志、会话内容和工具事件中没有该原值。目标配置文件是明确允许含原值的例外。

覆盖跨会话引用、未知引用、恶意目标、重定向、路径穿越、符号链接、并发编辑、特殊字符、超时、异常、取消和代理重启。不用真实用户凭据测试。

### 阶段 C：供应商与隐私能力对齐

实现模型隐私等级、降级保护、工具来源报告、会话控制；完成 ZDR 实际请求测试和受支持供应商的 TEE 连接绑定验证。验证失败不得展示“已验证”。

离线 fixture 测试只能证明解析和决策，不冒充真实供应商验证成功；真实网络集成状态单独显示。

### 阶段 D：扩展兼容性

增加 CLI/MCP 和其他平台存储适配器。发布逐项 pi-privacy 功能对应表、安装说明、兼容版本、已知缺口及端到端测试结果。
